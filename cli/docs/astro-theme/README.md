# Shared documentation frontend

The CLI embeds this private Astro 7.3.5 / Starlight 0.42.4 application. Use Node 24 and npm (minimum Node 22.12), with no separately published frontend package. The CLI stages files, runs `npm ci`, then `npm run build`. `ANDROID_REPO_DOCS_OUTPUT` selects the absolute final output directory.

The stage supplies `pages.json`, `scopes.json`, `site.json`, and immutable assets and raw guides in `public/`. Pages are Markdown data, never imported MDX or scripts. Explicit Zola heading suffixes `{#anchor}` become HTML heading IDs; raw HTML is omitted. Navigation preserves supplied scope URLs, including repository deployment prefixes. Version/language changes preserve the current guide where available and otherwise open the selected scope's overview. The sidebar lists the selected scope only. Home selects the highest stable semantic release; development is labeled explicitly. Single-module sites redirect directly to that release.

Current trusted repositories may customize `sites/astro/components/ScopeBanner.astro`, `sites/astro/components/ScopeSidebar.astro`, `sites/astro/components/ScopePageTitle.astro`, `sites/astro/components/ScopeHead.astro`, `sites/astro/components/ScopeSearch.astro`, `sites/astro/components/ScopeMarkdownContent.astro`, `sites/astro/components/ScopeLanguageSelect.astro`, or `sites/astro/styles/docs.css`. The CLI copies these directories over shared components/styles. Other components may be imported by overrides. Public overrides in `sites/astro/public` are copied before canonical assets. Treat `.astro` overrides as trusted executable build code; historical documentation never supplies overrides. Repositories need not copy this package or lockfile.

Run `npm test` for navigation, semantic ordering, anchor conversion, and input validation. After `npm ci`, run `npm run test:build` for isolated Astro builds at `/repo/` and `/`, checking generated links, anchors, raw links, provenance, fallback, selectors, scope-only sidebars, and latest-release home selection.

Search uses Pagefind with language, module, and version filters. Locales derive from staged scopes; each language home selects its own latest release. Immutable `scope.images` are rendered only on module overview pages. Production fixture tests execute the generated Pagefind JavaScript and WASM, checking all three scope filters and deployment prefixes.
